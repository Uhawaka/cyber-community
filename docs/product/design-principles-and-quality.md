# 设计理念与整体质量模型

本文回答三个问题：这个产品为什么存在，什么样的实现仍然算同一个产品，以及如何判断一个世界是否真的“活起来”。它是产品与技术决策的最高层评估依据；具体格式和接口以规格、ADR 与代码为准。

## 1. 产品命题

生成式世界引擎不是替用户写完剧本，而是帮助创作者定义一个能够自行运行的世界：

```text
创作者意图
→ Agent / World IDE 辅助形成世界包
→ Workflow 规定世界如何创生、演化、接受介入和交付内容
→ Runtime 让角色与世界持续互动
→ Event Log 形成不可逆历史
→ Narrative Curator 定期把历史加工为值得追更的剧情
→ 用户观察、选择或以 Avatar 参与
→ 世界继续运行并承担后果
```

产品价值来自“规则产生了作者没有逐场写下、但回看时合理的历史”。如果主要事件、走位、台词和结局仍由作者预排，系统即使使用了模型，也只是剧本播放器。

当前实现只覆盖从已完成目录世界包到运行、参与和文字交付的技术纵切。World IDE 与创作 Agent 属于目标产品，但尚未实现。当前 `genesis` Workflow 负责确定性装载已编写资产，并不会调用模型即时生成完整世界。

## 2. 十条设计原则

### 2.1 世界优先，剧情后生

作者定义初始条件、角色、空间、资源、规则和干预边界，不定义每场戏。剧情是世界历史经过选择和文学加工后的投影，不是 Runtime 的输入。

判断问题：删除所有 Presentation 后，世界是否仍能独立推进并产生不同历史？

### 2.2 Workflow 是世界宪法，不是剧本

Workflow 描述创生、演化、介入和呈现的机制顺序与策略。它可以规定“何时检查事件”“怎样衰减需求”，不能规定“某 Tick 谁说哪句话、谁必然获胜”。

当前 Workflow 是四条封闭 typed 执行链，而不是任意 DSL。扩展应先证明稳定语义，再晋升为通用 capability。

### 2.3 角色是持续决策者，不是台词皮肤

角色行为至少受 profile、Soul、Memory、需求、能力、位置、关系和短期计划共同约束。模型只能在合法机会中选择或表达，不能凭文本绕过知识、成本和空间限制。

好角色并非永不变化，而是变化有跨时间证据；同样输入下的行为可以不同，但应能从其经历与处境中解释。

### 2.4 地点必须具有因果性

地图不是背景图。地点决定可达性、共址、资源、危险、权限、公开历史和可执行动作。移动必须有时间或机会成本；角色选择地点应有目的，停留也应有收益。

判断问题：修改通路或资源后，事件链是否真的变化？

### 2.5 历史先于记忆，记忆先于叙述

Event Log 是客观动态事实源；Projection 和 Memory 可由历史重建；Presentation 只读历史。角色可以遗忘、误解或形成低置信 belief，但系统不能把渲染文本反写成已发生事实。

### 2.6 两个导演严格分权

Simulation Director 只能选择作者授权的结构化 incident，并通过 Resolver 与 Event Log 提交后果。Narrative Curator 只能从已发生历史中选择焦点、因果链和交付窗口。前者不能写戏，后者不能改世界。

### 2.7 用户是世界参与者，不是结果编辑器

用户 Avatar 与 NPC 共享地图、知识、资源、成本和 Resolver。用户提交的是行动尝试；世界决定是否合法并承担后果。UserGate 用于真正需要用户选择的关口，不应用来掩盖 Runtime 无法自主行动。

### 2.8 长叙事来自连续性与编辑，而非无限日志

持续运行只产生历史，不自动产生好故事。每次交付必须围绕有限时间窗、焦点人物、状态变化和因果链组织；重复移动、等待和内部调度噪声应被压缩或省略。Episode 要留下可追踪来源，但不应读起来像事件列表。

### 2.9 事实确定性与表达生成性分离

同一世界 revision、seed 和输入必须可 replay；文学表达可以重渲染。模型失败、超时或越界时，世界事实不受影响，交付层可确定性回退。

### 2.10 有限预算与可观测失败优于假装无限

行动、机会、事件、记忆、catch-up 和模型调用都必须有预算。暂停、截断、拒绝和降级是合法结果，但必须可诊断。系统不得用静默丢失、隐式补写或不可解释的随机性维持“世界还在运行”的表象。

## 3. 整体质量模型

质量评估分为硬门禁、系统质量和体验质量。三者不能互相替代：测试全绿不等于内容好看，文本好看也不能掩盖历史造假。

### 3.1 硬门禁

任一项失败，运行结果均判定为无效，不参与体验评分：

1. **事实完整性**：只有合法 Event Log 追加能改变运行事实。
2. **可重放性**：相同 revision、输入和 seed 可重建相同状态与历史 hash。
3. **边界完整性**：Narrative、模型和世界包文本不能绕过 Resolver 或回写事实。
4. **知识与权限安全**：角色和 Avatar 不获得不可见来源、未授权能力或越界资源。
5. **原子性**：失败动作、介入和持久化不能留下半提交状态。
6. **可终止性**：预算和停止条件有效，不出现无界循环或失控模型调用。

### 3.2 系统质量维度

每项采用 0–4 级评分：0 为缺失或破坏性失败，1 为偶然成立，2 为基本可用但明显脆弱，3 为稳定达到目标，4 为跨世界、长时段仍稳定且有充分证据。

- **因果可信度**：每个重要变化能追溯到规则、行动、资源或介入；没有凭空高潮。
- **角色自主性与一致性**：行动由角色状态和处境驱动，变化有记忆与证据支持。
- **空间与物质约束**：位置、通路、容量、资源和成本真实影响选择。
- **时间连续性**：短计划、长期目标、冷却、承诺和未决事项能跨 Tick 延续。
- **涌现多样性**：不同 seed 或合理扰动产生有意义的历史分叉，而非仅文本措辞变化。
- **机制稳定性**：冲突、拒绝、重规划和降级处于合理比例，不被内部抖动主导。
- **可解释性与可观测性**：事件、决策、失败、预算和来源都能被定位。
- **可扩展性**：同一执行器可运行多个世界，不含题材专名，也不依赖作者代码。

### 3.3 体验质量维度

- **可读性**：Episode 有清晰焦点、时间范围和因果线，不泄漏运行器术语。
- **文学加工**：文本有节奏、场景与信息取舍，不是换连接词的流水账。
- **信息增量**：每次对话或交付带来新事实、关系变化、计划推进或悬念。
- **追更动力**：结尾保留由世界状态产生的未决问题，而非强造悬念。
- **参与意义**：用户选择能形成可观察、可解释且非预定的历史分叉。
- **角色依恋**：角色长期保持可辨识的价值、语言和关系轨迹。
- **创作者可控性**：作者能理解规则影响、比较 revision，并锁定不希望 Agent 改写的部分。

体验质量最终需要人工盲评和真实用户实验。自动指标只能发现退化，例如重复率、无效往返、拒绝比例、Episode 长度和来源覆盖率，不能单独证明“文学性”或“好看”。

## 4. 评估方法

每次质量评估应同时保留四类证据：

1. **契约测试**：验证硬门禁、失败路径和模块边界。
2. **固定 seed 模拟**：与基线比较事件分布、状态差异、重复和预算。
3. **扰动实验**：只改变一个世界规则，确认因果链按预期变化。
4. **人工评审**：在不知道版本的情况下评估角色可信度、可读性和追更意愿。

建议每个候选版本至少运行：

- 两个题材不同的世界包；
- 短程 20 Tick 与中程 100 Tick；
- 不少于 8 个固定 seed；
- 一次 UserGate 或 Avatar 分支；
- 一次无模型确定性运行和一次显式模型渲染运行。

### 4.1 暂定发布线

发布线用于阻止明显退化，不是最终商业标准：

- 所有硬门禁必须通过；
- 系统质量各项不得低于 2，因果可信度、角色一致性、时间连续性不得低于 3；
- 读者正文中的内部调度事件为 0；
- 相同对话主题不得在冷却窗口内重复；
- 关键 Episode 的每个事实都能追溯到来源事件；
- 人工评审不能主要把正文描述为“日志”“模板复读”或“角色随机游走”。

具体数值阈值必须通过实验校准，不能为了通过门禁而反向优化无意义指标。

## 5. 典型反模式

- 把冲突、角色弧、台词、走位或结局藏进 Workflow。
- 让大模型直接返回世界 Delta，再由系统无条件接受。
- 用随机事件数量代替角色主动性。
- 每个 Tick 都生成正文，或把全部未呈现事件塞进一篇 Episode。
- 角色目标完成后不断随机移动，以“活跃”伪装世界活性。
- 用 Soul 高频变化制造成长，导致人格漂移。
- 用 UserGate 让用户替 Runtime 决定所有关键行为。
- 只在一个世界、一个 seed 上调参，并把偶然结果提升为通用机制。
- 以测试数量、事件数量或模型调用成功率宣称产品质量完成。

## 6. 决策优先级

发生冲突时按以下顺序取舍：

1. 事实、安全和可重放性；
2. 角色与世界的因果一致性；
3. 用户行动的公平性和可解释性；
4. 长期运行稳定性；
5. 叙事可读性与文学表现；
6. 性能、成本和创作者便利；
7. 新功能数量。

文学表现不能破坏事实边界，但这不意味着文学质量可以无限后置。当前纵切已经证明边界可行，下一阶段的主要目标应从“有没有机制”转向“机制是否持续产生值得追更的历史”。
