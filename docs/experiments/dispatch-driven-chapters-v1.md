# 调度驱动章节 v1

## 假设

章节又短又慢，是因为每个角色回合都经过环境裁决，再被文学管线重写成另一篇；场景一收束就切章。对白本身就应该是章节材料。思考和对白不加载环境，环境只在共享事实变化时加载。一条调度链完成之前不切章。

## 机制

- 角色意图携带 `dispatch`：`think`、`address`、`act`。声明为 `think` 的回合保持为思考，即使引用了物件或锚点。
- `think` 只提交自己的回合。没有说出的话、也没有公开决定时，不进入读者窗口。
- `address` 提交原话，并立刻加载被点名的角色或 NPC。对方的回应留在同一条链上，链深上限 6，用来防止循环，不作为减少对谈的手段。NPC 的公开行动写原话。
- `act` 才调用环境裁决。
- 还在等同一个人回答时，别人再换一种说法追问，记为无进展。连续无进展才抬高场景压力。这个问题还开着时，不能离开这一处。
- 每个回合只推进一处尚未收束的场景。已经在进行的处所优先，收束后才转到下一处。
- 写明了 `location_id` 的事件和选择，等到还有人在那一处才发生，并带上该处的场景。没有人在场时不插入别的章节。
- 同一处收束后，一个回合只送出一批去向相同的人。新到的一处还没有人作出决定时，其他人不能另开去向。只有这一处已经形成阅读弧，下一处的事件才会结束这一章。
- NPC 已经说过的目击不再重复，也不再算进展。引擎生成的“阶段结果”套话不进入正文。没有公开决定的思考不进入正文。
- 章节不再按 episode 的事件数或时间跨度切开。写作模块每次只看到当前这一处，以及下一处的开头，自己选定收在分界之前的哪一条。已经离开的一处不再继续等待。同一条 `chain_id` 不会被拆开。没有写作模型时，有下一处就收到离开之前；否则退回“一段已经结束、并且已经产生后果的内容”。
- 已有双方对白的章节按对话链装配已提交原话。场景规格句不进入正文。事实和文风门禁不变。对白不足的章节仍走文学管线。
