## 假设

如果角色决策能携带目标、公开知识和 DialogueAct，事件能携带授权地点/资源
上下文，策展围绕变故与选择过滤低信号动作，再由专业写作 Skill 执行初稿和
事实/行文终审，那么同一段自主历史可以被写成事实安全且接近专业类型小说的
单场景。

## 改造

1. 三名角色从同一后门出发，争夺唯一铜铃片；Tick 3 发生逆风铃响，Tick 6
   打开残火 UserGate。
2. 对话从 stock greeting 改为 `inquire/disclose/propose/challenge/reassure`，
   台词只能引用公开 Memory；`visibility: private` 的经历不可自动披露。
3. 采集竞争失败会转为与持有者协商；重复执行同一计划目标的奖励会快速饱和。
4. Digest 保留地点、目的地、资源和 DialogueAct 等授权上下文；策展计划只把
   对话、采集、incident、UserGate 和用户介入等高信号事件交给模型。
5. `scene-craft-v2` 执行八遍写作方法；模型先写初稿，再独立执行事实与行文终审。
6. UserGate choice 可提交可观察结果；CLI `--gate-choice` 应用选择后继续剩余 Tick。

## 迭代证据

- 早期确定性轮次消除了内部调度文本，但只是安全的场景梗概。
- 第 9 轮 35B 初稿具有画面感，却补写了低头、触摸、退步、内心活动和鞋底/
  袖口痕迹；这证明“读起来像小说”不能替代事实审计。
- 双遍终审、中文引号识别和无来源内心活动门禁拦住了上述越界。35B 仍会错置
  说话人及事件顺序，属于指令遵循上限。
- 125B 能通过来源、说话人和顺序门禁，但容易退化为“某人观察/注意到/面临
  选择”的事件报告；新增质量门后不再发布这类候选。
- 第 17 轮输出事实一致、顺序稳定、选择明确，仍以信息转述为主，场景动力、
  潜台词、人物声音和结尾余味不足，不能判为专业成稿。
- 事后机制审计发现两处事实漏洞并已修复：地点观察曾从静态世界定义报告已经
  拾空的资源；Resolver 的披露授权曾遗漏 `visibility: private` 检查。黑松岭
  的“细线/粉末/细痕”也已统一为“骨白粉痕”，UserGate 文案不再假定所有角色
  已经同处殿内。

独立严格终审给出 30/80（3.75/10）：人物可信度 4、场景动力 3、潜台词 2、
节奏 4、画面 5、语言辨识度 3、结尾余味 3、事实一致性 6。主要证据是核心
粉末命题复读、沈砚投放信息后消失、逆风铃响没有触发行动，以及结尾仍是产品
交互问句而非动作、发现或局势改变。

## 结论

机制假设部分通过：系统已经能从自主历史中选择单场景材料，约束知识披露，
执行模型初稿/终审，阻止明显事实越界，并让用户选择形成真实可重放分支。

专业文学质量假设失败。根因不只是模型或 Prompt：当前 Runtime 事件记录“做了
什么”，却缺少对话命题的共享会话状态、场景内可观察反应、角色对线索的即时
判断及选择后的连续压力。叙事层若自行补齐会越过事实边界；不补齐则只能写成
清楚的梗概。继续堆文风词或放宽事实校验会制造虚假进步。

## 下一轮

1. 增加 typed `ConversationState`：上一命题、已披露 fact、未回答问题、立场和
   会话目标，避免各角色独立抽取 Memory 后互相错题。
2. 把无世界状态影响的“场景实现许可”正式建模，区分材料事实、可选舞台动作和
   禁止虚构内容，而不是只靠 Prompt 约定。
3. 让 Resolver 提交可观察的行动方式与即时反应，但不预写剧情或角色结局。
4. 用匿名人工评审比较 Runtime 改造前后样本；自动门禁只负责拒绝退化，不负责
   宣称文学性。
5. ScenePlan 在发布前验证目标、阻力、赌注、主转折和场末状态差；面向连续阅读
   的成稿不能直接以 UserGate 的 UI 问句代替文学结尾。
