# EXP-20261017-011：机制优先的文学质量循环

## 目标

在不为单篇成稿硬编码世界事实、不放宽事实门禁的前提下，循环定位素材、策展、
Skill 与 Voice 四层问题。退出线设为匿名八维评审至少 64/80、无单项低于 7，
并胜过冻结基线。

## 机制调整

- 文学 CLI 与 Story Delivery 统一读取编译后的 Editorial Contract；
- 场景中的作者定义资源作为规范物件注入，模型只能安排位置，不能改写名称、
  描述和属性；随机陈设与规范物件分离；
- 被拒绝的无结果回合、无进展环境 NPC 回合不进入读者材料；
- 环境 NPC 可携带最多三条首次渲染时提交的本地见闻，只有实际披露见闻才标记为
  `advance` 并进入策展；
- NarrativePlan 按 opening / pressure / development / turn / aftermath 的戏剧
  功能分组，不再固定每四条日志切一段；
- 写作与修订阶段只接收获准引语摘录；短术语引号与直接引语分别校验；
- Scene Writer、Line Editor 增加证物保管链压缩、段落压力变化和具体名词审计；
- 场景自动收束只提交通用结果，个体决定保留在结构化来源中，不再由 Runtime
  拼接题材专用的“保管与去向”长句；
- 文学阶段对来源全局倒序和遗漏提供一次有界结构重试，失败后仍确定性回退。

## 证据

世界运行样本位于 `outputs/quality-loop/`：

- `round-03-current` 首次证明引用隔离和环境回合过滤可自动通过；
- `round-04-authored-items` 证明规范铃片及“入供”事实进入角色可见场景；
- `round-07-closure` 在五 Tick 内形成三方决定与阶段收束；
- `round-12-informed-npc` 证明 NPC 可披露已提交本地见闻；
- `round-14-compact-outcome` 证明 Runtime 的通用收束结果不再泄漏具体题材。

冻结素材编辑中，`round-10-candidate` 为本轮最佳盲评样本。它相对旧体验契约
基线获胜，单次评审为 62/80 对 51/80；复评为 61/80 对后续世界样本 54/80。
其人物可信度、意象、潜台词和结尾达到 7–8 分，但节奏与场景动力仍只有 7 分。

## 结论

机制修复有效，但本轮没有达到预设的 64/80，因此状态仍是 **verified**，不是
**quality-validated**。当前瓶颈不再是日志转写或事实泄漏，而是角色常以不同措辞
重复证物保管规则；新 NPC 见闻虽能进入事实链，发展编辑仍可能不让它承担转折。

下一轮应在多 seed 上评估“决定语义去重”和“证词是否改变选择”，并对同一冻结
素材采用多候选盲选，测量模型方差；不得以挑选单篇高分样本冒充稳定质量。
