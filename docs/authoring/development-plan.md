# 后续开发规划：通用接地系统

2026-08-21。本文是开发方向，不是 WDL 规范。规范仍以 `docs/contracts/` 为准。

## 要做的产品

构建**虚拟社区**，让角色产出**有趣、且符合该世界预设世界观**的素材。不是构建非常专业的 agent。

深度来自大模型自己的知识储备和角色性情；世界只声明世界观与「什么算出场」。检索不是默认。我们的工作止于：编排共同生活、卡住出戏的材料、把明显出戏的输出挡在世界观外。角色会不会算对、会不会按手册操作，不是本项目要解决的问题。

## 这不是专业 agent 项目

Invest agent 的教训：花大量时间写 skill 和 workflow，agent 仍经常犯错、不按 skill 工作。把角色做成「会自主研究量化 / 数论的专家」极难，而且**不是我们的工作**。

因此：

- 少写、短写 skill。长手册挡不住胡来，只会变成没人遵守的说明书（数学公社已经试过把宣言倒进提示）。
- 引擎不追求「按 skill 正确执行」。硬门只拦**出戏**：空转当工作、窗外货架进了不该进这个世界的东西、对外发言完全没有对象。
- 有趣来自碰撞、卡点、性格摩擦，以及模型在世界观里即兴。正确来自偶发，不设为验收条件。

「随机控制能把公式推明白」是素材好看时的上限，不是岗位。验收看是否像这个世界里的人在过日子，不看有没有推进 BSD。

## 为什么先拿数学公社做实验

数学门槛高，绝大多数人在门外。这反而适合当开发的金丝雀：

- **外行都能闻出不对，就一定是胡言乱语。** 开发者不必是数学家。名词堆砌、对象失踪、HEP 冒充数论，门外人也能嫌别扭。这比「看起来挺专业」更硬。
- 机制过了这关，再换爱好者更多的世界（历史、影视、诗）。那些社区里稍有年代、史料、典故上的瑕疵就会被看出来；数学门外人测的是「还在不在胡说」，历史爱好者测的是「细节出不出戏」。先过粗筛，再过细筛。
- 因此数学公社留下当第一实验世界。不是为了培养数学家，是为了用最高的「文盲可检测性」把通用门调稳。历史社区等 P0–P2 过关再开，不要平行开第二条专家线。

## 诊断：失败在设计，不在「没检索」

本地和云端大模型都已经能讨论很专业的问题。诗社（enclosed、无窗外）这条路径本来就成立。数学公社前几天像文盲拽名词，主要不是模型不懂数论，而是回路在惩罚深度、奖励表演：

- 激活被收件箱 / 碰撞占满，研究变聊天
- `observe_world` 自动拿任务卡去搜，检索变成义务而不是选择
- 十轮内心对话算作「一天的工作」，却没有任何可指认的对象
- 深度反思无出处也进公共产出
- 口号式 query、`all:` 无分类——一旦强制检索，Day 5 还把 HEP 送上架，比不检索更糟

结论：**完全关掉检索，只靠模型知识和一套「必须对着对象干活」的门，按理就能做出外行觉得有深度的社区。** 前面的实验没有证明「必须检索」；它证明了「设计不合理时，检索和聊天都会变成拽名词」。

检索仍保留在工作流里，但是**需要时才搜，不是必须搜**。节奏可以继续给「观察窗外」留位子，角色也可以选搜；引擎不得把搜索当成一天的及格条件，也不得替角色编关键词。

关键词必须来自 agent 自己：它在单元里卡到「这一点我知识储备不够 / 我要核对原文」时，才提出 query。引擎用任务卡、`current_focus`、领域词表去 `salvage` 出一条查询，是在替蠢角色装懂——它不知道找什么、也判断不了命中，搜了只会污染未读架（Day 5 的 HEP）。角色搜得蠢，就应留下「不会搜」的痕迹，而不是系统补一句 `open problems mathematics`。

**初期实验先关搜索**（不注册 `search_*`，或不排程 `observe_world`，或世界开关 `literature.enabled: false`）。知识社回路（对象、单元、对外要有物件）够稳之后，再打开「需要时由 agent 发起」的检索。货架过滤（`cat:`）属于打开之后的附件，不是开搜之前的前提。

## 三层分工（只做一次引擎）

| 层 | 作者填什么 | 不填什么 |
| --- | --- | --- |
| **世界** | 世界观、窗、工具、两三句什么算出场 / 出戏 | 领域讲义、专家操作手册、检索算法 |
| **角色** | 嗓音、怕什么、谁拍桌子 | 专家履历、量化/数论 SOP、名人模仿 |
| **引擎** | 共同生活 + 挡出戏。可选：按需检索 | 保证算对、保证遵守 skill |

大模型负责行话和已知文献。系统负责：空转的流畅发言不算工作。世界作者不需要先成为该领域专家。

三种世界模式（同一套引擎）：

1. **知识社**（默认，初期实验）— 搜索关闭。工作单元来自模型已知对象 + 本地工具（写、算、改）。
2. **封闭社** — 已有：诗社 / 哲学咖啡馆。无窗外。
3. **按需检索** — 机制够稳后打开。角色自己决定是否搜、搜什么；引擎不代写 query，不因「今天还没搜」扣分。
4. **前沿社** — 按需检索 + 货架。只为紧跟预印本 / 活奖单。

## 已落地（不要重做）

1. **工作义务（SOP）** — `engine/work_queue.py`：若发生了检索，命中进未读架，不得写成「读了」；公共制品要有可检验对象或角色正在对付的对象。
2. **角色技能** — 目录只开书，不倾倒宣言进每个提示。
3. **Live 建社 / 批跑续日** — 产出锁在 `outputs/<world-id>`；`run` 从当前时钟推进。
4. **P0 知识社（2026-08-21）** — `literature.enabled` 默认关。无角色 query 不搜。连聊后回到 study，不强制 `search_arxiv`。不排程自动 `observe_world`。
5. **P1 对外要有对象（2026-08-21）** — 无 `working_object` 不得把社交/集会当发表（收件箱回复除外）。碰撞/回响/深思上墙须点名对象；没有对象的碰撞只准问一句。
6. **P3 按需检索（2026-08-21）** — 数学公社已打开。`search_*` 重新注册；query 只接受角色当次字符串；口号 / 空词 = 不会提问，不代搜。仍不自动排程观察窗外。
7. **货架 + 对象门（2026-08-21）** — `cat:` 上架前丢掉越界分类。认对象看专名（Cook–Levin / BKM / Hodge），不要求整句 `working_object`；「从验证转向」不得覆盖桌上的名字。

这些门仍然有用。未读架只在角色自己搜出命中之后生效。

2026-08-20 续日：SOP 会响，同时证明强制检索在分类缺失时会污染货架。不要把「修检索」当成下一件必须做的脊柱工作。

## 明确不做

- 再写一套「非常专业的 agent」skill / workflow（invest agent 已证：贵且不听）
- 按领域手写专家长人设，换方向再走一遍
- 把 skill / 世界 YAML 当百科倒进提示
- 第一刀上嵌入、STORM、MCP 包一层同一 Atom API
- 用换模型代替改回路（更强模型会更流畅地空转）
- 把「每天搜 arXiv」或「攻击千禧年问题」写成社区身份
- 无分类的 `all:`（若某世界打开了检索，仍禁止）

开源检索栈（`cat:`、上架前拒掉分类外命中）只在**前沿社**启用时才借鉴。不是知识社的前提。

## 路线图

### P0 — 知识社回路（先改设计，检索可关）

目标：关搜索时，一天仍能留下**符合世界观、且有对象**的素材（一场争执、一段推导、一稿、一次算砸）。不要求专业正确。

- 初期实验：**关掉搜索**（工具不注册或世界开关），不删工作流里的搜索节点。
- 以后打开时：搜索是角色决策，不是义务。禁止引擎用任务卡 / focus / 词表代写 query；不会写关键词 = 这次不搜或搜失败，算角色能力，不算系统要补的坑。
- `observe_world` 若保留，只在角色选了「看窗外」且自己给出 query 时发请求。没有 query 就站在窗边，不替它搜。
- 工作单元（已有 `world.research`，领域无关）成为激活的主出口：重建一条已知论证、写出一场戏、跑一个能死的探针、记下卡点。完成单元 = 当天成功。
- 「物件」的定义放宽为领域无关的三种之一即可：
  1. 点得名的已知对象（定理、剧本结构里的一场、一首被引用的诗）+ 一句可核对的陈述
  2. 一次本地工具痕迹（代码输出、一稿正文）
  3. （仅前沿社）一段检索/深读摘录
- 无物件的深度反思可以进灵魂，**不进**公共产出（已有门，保持）。
- 收件箱不再压死「对着对象工作」。没有未读论文不得强制 `search_arxiv`。
- 测试不依赖外网：搜索关闭时一日能跑完；无物件洞见不进 production；引擎不得在角色未提供 query 时发出检索。

验收：外行觉得这些素材属于这个世界，并且不是纯开会拽名词。算错、搜错、性格别扭都算素材。出戏（HEP 进数学公社、诗社谈 API、空转当日报）算失败。

### P1 — 对外发言：有对象才能发表（已接入）

目标：碰撞和黑板不是名词展览。

- 对外（collision、gathering、制品、回响）必须带上当前工作单元里的对象名称或工具痕迹。做不到：只能提问或回去干活。
- 不要求 arXiv id。要求「说的是哪一个东西」，而不是「听起来像这个行业」。
- 提示词只提醒；拒绝由引擎做。

编剧世界和数学公社共用这道门。差别在对象种类，不在引擎 fork。

### P2 — 单角色验收，再看社区

- 不新写专家 YAML。用现有角色 + P0/P1 跑一个虚拟日。
- 外行嗅探（开发者本人即可）：
  1. 这些材料像这个世界里的人在过的日子吗？
  2. 有没有一个对象（命题 / 场次 / 一稿），还是只有行话？
  3. 有没有出戏（错货架、错工具、世界观破裂）？
  4. 有没有意思（争执、卡点、性格），还是任务卡复读？
- 社区互审放到这项过关之后。文化仍写在 YAML。

**2026-08-21 嗅探**

- Yuki 单人：点名 Eisenstein at \(s=1/2\)，对着 Fourier / residue 卡住。门曾因句号认不出对象，已放宽。
- 多角度（隔离目录，未写 live）：Pavel 对 \(\zeta\) 写可死的 Lindelöf / moment；Yuki×Pavel 为 \(x^\rho\) 是单调还是振荡、整和会不会抵消而争执，Pavel 当场宣布自己的 kill criterion 不成立；无对象碰撞只问一句；访客拿 Clay/使命带偏时，Elias/Yuki 能回到桌上的对象。研究/碰撞提示不再倒 Horizon skill。YAML 里的货架嗓音被问及时仍会露一句，不算出戏。
- 单角色 + 一对碰撞可过关。整社区一日互审仍未做。

### P3 — 打开按需检索（已接入，数学公社）

- 搜索节点一直在工作流里，但默认关。P0/P1/P2 过关后再开。
- Query **只接受角色当次给出的字符串**。禁止 `salvage_search_query` 用使命/词表冒充 agent 意图。
- 角色给不出 query 或给的是口号：这次不搜，记一条「不会提问」，不要代搜。
- 命中判断也是角色的：引擎最多丢掉货架外分类（打开前沿货架时）；相关性仍由角色决定读哪一篇。
- 未读架、深读义务仅在角色自己搜出命中之后生效。

货架 `cat:` 已接入（数学公社：`math.*` / 复杂性 / YM 用的 `hep-th`·`hep-lat`）。上架前丢掉分类外命中。Semantic Scholar 仍未做。

## 创一个新世界

1. 选模式：知识社 / 封闭社 / 前沿社。默认知识社。
2. 工具：写、算、改——按领域选。检索工具只有前沿社才需要。
3. `world.practice`：两三句什么算干活（对着对象；探针能死；空谈不算）。
4. 角色：嗓音与怕空谈 / 怕独断。不要写操作手册。
5. 不要：专长地图、名人模仿、invest-agent 式长 skill、把「每天读新论文」写成社区身份。

第一实验世界固定为数学公社（关搜索的知识社形态）。历史等爱好者密集的世界放在金丝雀过关之后：同一套门，只换世界观。数学公社不要把 Clay 当唯一合法题目，否则素材会变成表演专家。
