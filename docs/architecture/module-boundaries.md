# 模块边界

当前运行结构见[当前版本结构](project-structure.md)。

## 依赖

作者源 → World Compiler → CompiledWorld → Community Runtime → Event Log。
角色上下文与记忆从世界和历史投影；模型只提出自己的行动，不能写事实。
观察和评审读取历史，不反向影响运行。

Contracts 不依赖引擎实现；World 不依赖 Runtime、Application 或 Narrative。
Runtime 不依赖 Application、Narrative 或具体 Adapters。
只有 Bootstrap 组合具体模型和存储适配器。

## 契约

- 世界编译只接受 `world-package/v1alpha3`，必须有 community asset 和 capability。
  作者数据、工作流和路径都须校验，不执行作者代码。
- 社区运行只接受显式版本化的社区世界。默认离线生活策略；
  只有显式模型配置才调用模型。
- 提案绑定本人、当前状态 hash 和本人可见来源，经注册动作裁决后产生事件。
  声明、表达、计划和承诺不自动成为事实或他人同意。
- 只有成功的原子事件提交能改变事实。失败不得部分扣材料、完成活动或修改历史。
- 个人库存、现场库存与其他人的库存分开，真实动作必须有材料和时间后果。
- 期限时钟独立；普通角色事件不能代替系统时间结算。
- 托管配置绑定世界、引擎、策略、模型身份和预算，变化时拒绝续跑。
- 恢复复用已记录响应，未决模型请求不得自动重试。恢复不能重置 Tick 预算。
- `run_community_catchup` 只执行真实详细 Tick，超出上限延后，不虚构粗粒度结算。
- 观察不得公开私人认知；管理员诊断和人工评审材料必须与公共观察分开。
- 评审包可包含单个合格的 100 Tick 样本，仍要求来源绑定和独立人工评分。
  空白评分、合成模型和测试中的合成评分不是质量验收。

## 验证

架构测试检查依赖方向和模块大小。行为测试覆盖来源越权、库存守恒、
活动和计划结果、模型请求落盘、事件前缀恢复、并发写入及损坏日志拒绝。
正式世界必须从统一作者源可重复构建。

旧场景执行器、导演、Avatar、文学发布和 v1alpha2 编译不属于当前版本，
不存在兼容转发入口。
