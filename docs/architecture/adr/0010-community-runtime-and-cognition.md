# 0010：社区运行、个人认知与版本迁移

状态：接受；当前实现和未完成项以社区架构及任务检查点为准。

## 决策

1. 社区包显式声明 `world-package/v1alpha3` 和 `community-runtime/v1`。
   托管运行绑定世界与引擎指纹；不静默切换运行语义。
2. 社区有一个运行内核；是否使用模型只替换 `CommunityPolicy`。
   旧公开运行入口、旧运行内核和体验配置合成回退已移除。
3. EventLog 仍是唯一提交入口。客观变化使用 Delta；个人经历、信念、
   目标、承诺和未决活动以有所有者、有来源、可验证的事件记录重建。
4. 运行游标、世界 revision、runtime version 和提交 id 均保存。
   会话线程仅是缓存，不能成为必须依赖的角色记忆。
5. 1 Tick 固定为 60 模拟分钟，24 Tick 为一模拟日；活动必须有正时长。
   模型暂停/超时不改变此时间单位；默认不每 Tick 唤醒每个人。
6. Soul 是稳定人物档案；MVP 冻结 Soul 演化，信念/情绪/计划/关系正常变化。
7. `MemoryRecord` 表示角色经历；`KnowledgeClaim` 表示主观知识及其渠道。
   “角色相信某件事”可以保存，但内容不会自动成为客观真相。
8. 感知只提供现场公开特征、实际接收的消息和已知通路。
   查看结果、秘密、作者压力、远处人物位置不进入未授权上下文。
9. adapter 将结构化意图转成注册动作和计划，规则校验资源、时长、
   技能、空间、所有权、双方接受与版本。任意自然语言意图编译尚未实现。
10. 每轮先验证、持久化，再更新投影。模型输出有来源引用与预算限制；
    重放保存事件，不再次调用模型。外部模型重新生成不承诺逐字确定性。

## 最小纵切

两名角色、两个地点、损坏的灯与材料库存。观察获取 condition claim，
维修占用两 Tick，消耗材料，修改灯状态；同一灯不能被重复占用。
另一人可以独立活动；材料不足/无技能/版本冲突时无半提交。
连续运行与中途恢复得到相同事实、记忆、未决活动和消息状态。

## 版本边界

当前社区入口不提供旧作者格式或旧托管配置的兼容续跑。保留已有历史，
不能以新实现伪造或重写；旧 v1alpha2 编译及运行路径已退役。

## 契约

已定义于 `engine/contracts/community.py` 与 `cognition.py`。
运行校验继续验证跨字段的所有权、来源可见性和引用存在性；
数据类自身校验不能替代权限裁决。

## 验收与预算

主计划行为门槛保持为
重要行动解释率 >=80%、无进展重复 <=15%、每 100 Tick 至少三条
角色发起的跨日因果链；关键事实/知识泄漏/半提交零容忍。
当前优先使用单世界有界模型样本修复机制，不进行多 seed 扩样。
正式 100 Tick 人物和剧情质量门禁通过前不运行 1000 Tick。
人工人物和剧情质量保持待验证，不以自动测试代替盲评。
